## 1. システム概要

### 1.1 プロジェクト概要

RTL-SDR デバイスから取得した IQ サンプルを FM 復調し、ステレオ音声を
リアルタイム再生・録音するアプリケーションです。復調・ステレオ分離・
ノイズリダクションはすべて Python（NumPy / SciPy / Numba）で実装され
ています。

### 1.2 主要機能

- RTL-SDR による FM 放送受信
- arctan discriminator ベースの FM 復調（レガシー PLL 経路も選択可）
- ステレオ / モノラル出力（パイロット SNR 連動の適応ブレンド）
- Mid/Side スペクトル雑音抑制（side チャネル専用 DD-Wiener STFT）
- ソフトウェア自動ゲイン制御（AGC）
- リアルタイム音声再生・録音（音声 WAV / 生 IQ WAV）
- 4 GiB を越える長時間録音の自動ローテーションとメタデータ記録
- 合成 IQ / 実測 IQ による品質セルフテスト

### 1.3 技術スタック

| 分類 | 使用技術 |
|------|---------|
| 言語 | Python 3.11+ |
| 数値計算 | NumPy, SciPy |
| 高速化 | Numba（JIT） |
| SDR | pyrtlsdr（librtlsdr） |
| 音声 | PyAudio（PortAudio） |
| テスト | pytest, GitHub Actions（Ubuntu / Windows） |

### 1.4 動作モード

| モード | サンプルレート | 復調方式 | 用途 |
|--------|--------------|---------|------|
| 標準（Standard） | 1.024 MHz | arctan discriminator（既定）/ PLL | 通常受信 |
| 軽量（Light） | 250 kHz | arctan discriminator | 低 CPU 負荷 |

`--light` の既定はモノラルですが、`stereo on` でステレオに切り替える
と標準モードと同じステレオ復調パイプラインを通ります。

## 2. システムアーキテクチャ

### 2.1 全体構成

```
┌─────────────────────────────────────────────────────────┐
│                  FMReceiverController                     │
│  （全サブシステムを統合、facade API を CLI へ提供）        │
├───────────────┬───────────────┬───────────────┬──────────┤
│ SDRReceiver   │ FMDemodulator │ AudioOutput   │ AutoGain │
│ （IQ 取得）    │ （復調）       │ （再生 / 録音） │ Controller│
├───────────────┴───────────────┴───────────────┴──────────┤
│                CommandLineInterface（対話 CLI）            │
└─────────────────────────────────────────────────────────┘
```

### 2.2 スレッド構成

リアルタイム経路（SDR コールバックと処理スレッド）はディスク I/O や
USB 制御転送で決してブロックしないよう、遅い処理はすべて専用ワーカー
スレッドへ分離されています。

| スレッド | 役割 | 生成元 |
|---------|------|--------|
| SDR async read | rtlsdr ライブラリ内部スレッド。IQ ブロックを `data_queue` へ投入 | `SDRReceiver.start()` |
| Processing thread | IQ→復調→音声変換→再生キュー投入 | `FMReceiverController` |
| CLI thread | ユーザ入力の受け付けとコマンド実行 | `CommandLineInterface` |
| Audio callback | PyAudio コールバック。再生バッファへ供給 | PortAudio |
| AudioRecordWorker | 音声 WAV の書き込み（ディスク I/O 隔離） | `AudioOutput` |
| IQRecordWorker | 生 IQ WAV の書き込み（ディスク I/O 隔離） | `SDRReceiver` |
| AutoGainWorker | RTL-SDR の `set_gain()` USB 転送（同期呼び出し隔離） | `AutoGainController` |

### 2.3 リアルタイム安全性の設計

- **SDR data_queue**（最大 80 ブロック ≈ 1.28 秒）: 処理スレッドの
  一時的な遅延を吸収。溢れた場合はサンプルを破棄し WARNING を記録。
- **JIT プリウォーム**: 処理スレッド開始前に Numba / FFT の初回コン
  パイルを空 IQ で済ませ、起動時の ~1.3 秒スパイクによるキュー溢れを
  防止。
- **録音ワーカー**: `record()` / SDR コールバックは bounded queue へ
  投入するのみ。writeframes の 100–1000 ms ストールはワーカー側に閉じ
  込められる。
- **AGC ワーカー**: `set_gain()` の 40–200 ms USB ブロッキングを処理
  スレッドから隔離。要求は coalesce（最新値のみ反映）。
- **テレメトリ**: 処理スレッドが完成済み immutable スナップショットを
  スロットへ 1 回の属性再束縛で書き込む（GIL 下でアトミック）。読み手が
  止まっても処理スレッドは待たされない。ただしこの性質は**単一の再束縛**
  についてのもので、複数操作からなる手順には及ばないため、選局との競合は
  世代タグで無効化する。公開レートは 20 Hz、対象外ブロックの追加コストは
  比較 1 回のみ。

## 3. モジュール詳細仕様

### 3.1 コントローラ（controller.py）

`FMReceiverController` が全サブシステムを統合し、CLI へ facade API を
提供します。

主な責務:
- サブシステムの初期化（SDR / 復調器 / 音声出力 / AGC / CLI / 局リスト）
- 処理スレッドの実行（`processing_thread`）と per-block プロファイル
- 選局（`tune`）: 中心周波数変更・キューフラッシュ・復調器リセット・
  録音停止
- JIT プリウォーム（`_prewarm_jit`）
- ステレオ / モノ、録音、IQ 録音、AGC、ゲインの facade メソッド
- DSP 設定の facade（`get_dsp_defaults` / `get_dsp_settings` /
  `set_dsp_settings` / `update_dsp_settings`）。9 個のパラメータを
  再生したまま変えるための入口で、値オブジェクトは
  `dsp_settings.DspSettings`（フィールド既定値を持たない凍結
  dataclass）。既定は**走っている変種の復調器から** `capture()` した
  もので、constants.py の定数ではありません（標準 85.0 度 / 軽量
  84.3 度のように両者は一致しません）。
  変更は 1 個の再束縛で予約され、処理スレッドが**ブロック境界で丸ごと**
  適用します（`_take_any_dsp_change`）。`update_dsp_settings` は
  read-modify-write をロック下で行い、`set_dsp_settings` は 9 値
  まとめての last-writer-wins です。UI は 3.14.1
- 局リストの公開（`get_stations_list` はプリセット、`get_catalogue` /
  `search_stations` / `stations_in_area` は全件）
- ダイヤルの局名（`current_station` とスナップショットの `station`）は
  `area` で絞った**命名ビュー**を使います。全件ではありません — 周波数は
  全国で一意でないためで、3.9 に対照表があります。周波数をキーに
  キャッシュします

`_BlockProfiler` が per-block の処理時間・キュー深さを計測し、3 種類の
ことを言います（`--log` 時のみ）。

- **FALLING BEHIND**: キューが容量の 1/4 以上。即時、1 秒に 1 行まで。
  これは受信機が追いつけていない状態で、キューの先のサンプルは捨て
  られます。
- **SLOW BLOCK**: 20 ms を超えたブロック。5 秒に 1 行のサンプルで、
  その区間で**最も遅かった**ブロックについて、stage 内訳・キュー深さ・
  発生時刻・「何件中の最悪か」を書きます。後続が来ない停止は 60 秒
  サマリの直前と、処理スレッド終了時に吐き出します。
  実測では健全な受信中でもブロックの約 9% が 20 ms を超える
  （平均 10.2 ms、キュー最大 2/80）ため、1 件 1 行では本当の事象が
  埋もれます。
- **60 秒サマリ**: ブロック数・平均・最大・低速数・キュー最大。通算は
  ここにあります。
平均・最大・低速ブロック数・稼働時間はプロパティとして公開され、
テレメトリのスナップショットに載ります。

`get_status()` は現在の `StatusSnapshot` を返します。`None` になるのは
「まだ何も公開していない」「公開済みのものがすべて旧世代（選局前の捕捉）
である」「生成が失敗し続けている」の 3 通りで、この戻り値からは区別できま
せん。解消するのは次に公開が成功した時点で、通常は 1 公開間隔（既定 50 ms）
以内ですが、生成が失敗し続ける場合はその限りではありません。
世代は `SDRReceiver` が持ち、`set_center_frequency()` で進みます。各 IQ
ブロックは捕捉時の世代を伴ってキューへ入るため、選局前に捕捉されたブロック
（フラッシュ後に届く飛行中のブロックを含む）から作られたスナップショットは
公開されても配られません。

### 3.2 SDR 受信機（sdr_receiver.py）

`SDRReceiver` が RTL-SDR デバイスからの IQ 取得と、生 IQ 録音を管理し
ます。

- `read_samples_async` によるコールバック駆動取得
- コールバックは complex64 化して `data_queue` へ投入（非ブロッキング）
- 生 IQ 録音は `IQRecordWorker` へ委譲（ワーカー設計は §2.3、メタデータ
  は 3.12 参照）: flush sentinel、4 GiB ローテーション、書き込み例外の
  握り込み、メタデータサイドカー
- デバイスハンドルの状態と close は `DeviceHandle` が持ちます（3.2.1）

#### 3.2.1 デバイスハンドル（device_handle.py）

「いつデバイスに触れてよいか」「いつハンドルを解放するか」を 1 箇所に
まとめたものです。pyrtlsdr は制御書き込みや非同期読み取りが失敗すると
**その呼び出しの内側から自分で `close()` を呼ぶ**ため、close は呼んだ
スレッドも時点も選べません。`DeviceHandle` は `device.close` を自身の
`close()` に差し替えることで、その経路も含めた全ての close を 1 本に
します。

物理 close の前に満たす条件:

| 条件 | 守るもの | 待ちの上限 |
|---|---|---|
| 書き込みがデバイス内にいない（`device_lock`） | 書き込み中のハンドル解放 | `DEVICE_LOCK_TIMEOUT_SEC` = 5.0 s |
| C キャンセルが呼び出し中でない（`handle_lock`） | 生存確認と C 呼び出しの間の解放 | `HANDLE_LOCK_TIMEOUT_SEC` = 1.0 s |
| 非同期読み取りが終わっている | `rtlsdr_read_async` 使用中の解放 | `SAMPLING_CANCEL_TIMEOUT_SEC` = 2.0 s |

いずれかが期限内に満たせなければ **close は行わず要求を保留**します
（`close_pending`）。保留分は、デバイス操作の終了時（`held()` の解放時と
各操作の `finally`）、読み取り終了時、`stop()` のいずれかで果たされます。
再試行は**待ちません** — その時点でロックを持っているのは同じ操作群の
内側にいる誰かで、その者も出口で同じ経路を通るためです。GUI から呼ばれる
操作がロック待ちで固まらないのはこの性質によります。

読み取りの停止は C の `rtlsdr_cancel_async` を**直接**呼びます。pyrtlsdr の
ラッパーは C 呼び出しが失敗するとデバイスを close してしまい、失敗は
「読み取りが RUNNING 以外の全状態」で起きるためです。C 関数に到達できない
環境ではラッパーを使わず、読み取りをキャンセルしないまま残します
（ハンドルはプロセス終了で解放）。

### 3.3 FM 復調器（demodulator.py）

クラス階層:

```
FMDemodulatorInterface (ABC)
  └─ BaseFMDemodulator（共通フィルタ・復調・リサンプリング）
       ├─ FMDemodulator      （標準: discriminator / PLL）
       └─ FMDemodulatorLight （軽量: discriminator, パイロット LPF のみ order-1）
```

#### FMDemodulator（標準）

`process_iq_samples()`:
1. DC ブロッカ（複素1次 LTI ハイパス、fc=0.1 Hz、状態保持）。旧ブロック
   平均 EMA 減算を置換 — FM ではブロック平均が変調に支配されるため推定が
   揺らぎ、除去された成分が加法誤差となり、その位相方向成分 −Im(c·e^{−jφ})
   が discriminator の非線形性を介して変調相関の積(−22 dB)として composite
   へ現れていた（搬送波オフセット 0 の合成評価における「8–12 kHz セパレー
   ションディップ」の根本原因）。除去帯域を広げるほどこの誤差の入力電力が
   増えるため 0.1 Hz（旧 EMA の実効帯域と同一）を採用し、実キャプチャで
   pilot SNR は EMA と 0.01 dB 以内で一致。病理はノッチ遷移帯
   （おおむね |オフセット| < 0.1–0.3 Hz）で連続的に存在するが、本実機の
   実測残留オフセット ~60 Hz はノッチから十分離れている（合成の周期
   トーンは離散キャリア線がノッチに一致し得るため強く顕在化する）。
   LTI なのでブロック分割不変・0 Hz で厳密ゼロ・整定 ~1.6 s（EMA と同じ）
2. IQ ローパス（Butterworth N=5、SOS、ブロック間状態保持）
3. FM 復調 — 既定は **arctan discriminator**
   `angle(x[n]·conj(x[n-1]))`（前ブロック末尾サンプルを持ち越して
   ブロック境界で連続）。`MAIN_DEMOD_USE_PLL=True` でレガシー PLL 経路
   に切替可能。
4. IQ→composite リサンプル（`StatefulResampler` 3:16、Kaiser β=10）

discriminator を既定とする理由: PLL の閉ループ応答は MPX 帯域で
+3.9 dB のピーキングと 19k–38k 間で -30.7° の位相不整合を持つのに対し、
discriminator は全帯域で平坦・純遅延。合成 IQ でステレオセパレーション
が +4–6 dB 改善する。

#### FMDemodulatorLight（軽量）

`process_iq_samples()` は標準モードと同じ arctan discriminator
（`angle(x[n]·conj(x[n-1]))`）で FM 復調し、`StatefulResampler` 96:125 で
250 kHz→192 kHz に変換、`LIGHT_COMPOSITE_SCALE=0.35` を乗じます。以降の
ステレオ復調は標準モードと共通（mono/side FIR バンクも同一タップ数を共有。パイロット複素 LPF のみ order-1、SNR ノイズ帯 BPF は標準と同じ order-9 — 旧 order-1 流用はパイロット漏れで SNR を ~10 dB に飽和させ、軽量モードが full stereo に到達できなかった）。旧実装の
`angle→unwrap→diff` は unwrap 位相が搬送波オフセット下で無限成長し、
float32 量子化により長時間セッションで劣化するため置換されました
（伝達特性は同一）。

#### ステレオ復調（`_demodulate_stereo`）

`BaseFMDemodulator` の共通処理:
1. モノ抽出（15 kHz 線形位相 FIR、下記フィルタバンク）。mono/side の
   全フィルタが同一タップ数を共有するため両経路の群遅延は構造的に
   一致し、遅延補償は不要（`STEREO_MONO_DELAY_SAMPLES=0`）
2. パイロット抽出 — **ヘテロダイン方式**: composite を 19 kHz で位相
   連続にミックスダウンし、複素ローパス（Butterworth N=9、SOS、状態
   保持）で複素残差を得る。FFT Hilbert を用いない（ブロック端の位相
   グリッチが原理的に発生しない）。
3. パイロット SNR 推定（残差電力 `2·mean(|z|²)` と 2 本のノイズ帯の比）
   と適応ブレンド係数の更新
4. サブキャリア生成 `cos/sin(2θ + φ_offset)`（φ_offset は復調方式ごとの
   放送規格の +90° と DSP 補正 +1.0°/−28.9°/+0.3° の和
   （discriminator 91.0°/PLL 61.1°/Light 90.3°）に、実機では
   実録音の残差トリム `HARDWARE_SUBCARRIER_PHASE_TRIM_DEG`(−6°)を加算。
   cosine パイロットに対する副搬送波は −sin(2θ)（ITU-R BS.450-4
   §2.2.2.5）。旧 +84° はこの規格由来の +90° を含んでいたため、
   チューナ固有特性とは見なさない。通常受信の総位相は従来と同じ。
   これにより位相トラッカーの実機需要が ±90° 境界から 0° 付近へ移り、
   セッション間の取得枝（L/R 極性）が安定する）
5. L−R 帯の同期復調（DSB-SC、ゲイン 2.0）と 3 バンド LPF（I/Q 並列）。
   **前置バンドパスなし** — 理想的な 38 kHz 同期ミキサと **0–15 kHz の
   対象帯域内**では、raw composite 復調 + 15 kHz LPF は理想 23–53 kHz
   BPF を前置した場合と等価（モノ帯は 23–53 kHz へ、パイロット像は
   19 kHz へ移り LPF 阻止域）。これにより実 Butterworth BPF の帯域端
   特性（12–14 kHz の DSB 側波帯を削り HF セパレーションを崩壊させて
   いた実測要因）が原理ごと除去される。等価性は FIR の 15–18.5 kHz
   遷移帯には及ばず、帯域外 composite 成分（20.5–22 k / 54–56.5 kHz）
   が 16–18.5 kHz へ写像され得るため、最終音声帯域制限（下記手順 11）
   で抑制する。mono/side/3 バンドの全 7 フィルタ
   は同一タップ数（192 kHz で 321、群遅延 160 サンプル = 0.83 ms）の
   線形位相 FIR（Kaiser β=9、遷移 3.5 kHz、阻止域 ~−100 dB、19 kHz で
   実測 −102 dB）で、overlap-save（タップスペクトル事前計算）により
   任意ブロック長でワンショット畳み込みと厳密一致
6. I/Q 位相補正 — **ゲート付き4象限トラッカー**: 主軸推定
   `½·atan2(2·Cov, Var_I−Var_Q)` は ±90° 周期の曖昧性を持つため、
   (a) 共分散異方性 ≥ `STEREO_PHASE_ANISO_GATE`(0.2)、
   (b) side 電力 ≥ mono 電力 × `STEREO_PHASE_SIDE_GATE_DB`(-18 dB)、
   (c) side 電力 ≥ ノイズ推定 × `STEREO_PHASE_SIDE_OVER_NOISE_DB`
   (26 dB — FM ノイズは f² スペクトルにより side 帯で mono 帯より
   強く、かつ帯域非対称性で異方的な**疑似軸**を成すため、pilot ノイズ
   帯からの予測値で本物の side 成分と弁別)の全条件を満たすブロック
   のみで、π 周期族のうち現追跡値に最も近い候補への差分で EMA を更新
   （連続性が 180° 分岐を解決、クランプ不要で ±180° 追従）。更新の
   重みは異方性とノイズマージンの積（限界的ブロックはほぼ無重量）。
   ±90° 跨ぎ（= L/R 極性反転）は信頼度 EMA ≥
   `STEREO_PHASE_BRANCH_CONF`(0.7)の持続的な高信頼追跡時のみ許可。
   ゲート閉時は取得済みの角度を `STEREO_PHASE_LEAK_DEG_PER_SEC`
   (0.5°/s)で 0（トリム事前値）へ減衰。コールドスタート取得は連続
   `STEREO_PHASE_ACQUIRE_BLOCKS`(6)ブロックの倍角円平均
   `½·arg(Σe^{j2β})` で初期化（個々の生推定の ±90° ラップに不変）。
   取得時のみ「真の回転が ±90° 内」という FM 規格の pilot 位相規約を
   仮定。
   **どのゲートが閉じるか**（2026-09-21 実測）:

   測定上の注意。合成信号は離散スペクトル線の集まりで、**搬送波オフセット
   0 Hz では搬送波線が DC ブロッカ（0.1 Hz）のノッチに落ちる**ため、
   ゲートの読み値がゲートではなくその病理を測ってしまう。同じ −20 dB の
   番組で side-over-noise が 0 Hz では 25.6 dB、1237 Hz では 45.4 dB。
   以下の合成測定はすべて 1237 Hz（実機の残留オフセットは約 60 Hz、
   60 Hz と 1237 Hz は同じ値を示す）。

   合成信号（CNR 35、回転 30°、4 秒）で各ゲートを通過する割合:

   | 公称 | 実測 side/mono | (b) 通過 | (c) 通過 | 取得 |
   |---|---|---|---|---|
   | −10 dB | −9.5 dB | 100.0% | 100.0% | する |
   | −15 dB | −14.5 dB | 100.0% | 100.0% | する |
   | −20 dB | −19.5 dB | 0.0% | 100.0% | しない |
   | −25 dB | −24.5 dB | 0.0% | 100.0% | しない |

   きれいで十分強い信号では (c) は全く閉じず、閉じるのは (b)（−18 dB）で
   ある。−20 dB で (b) だけを開けば取得し、(c) だけを開けても取得しない。
   これが PR #49 の「信号は良いのに取得しない局」に対応する。ただし
   これは**きれいで大きい信号で番組が狭い場合**の話であって、局一般の
   結論ではない（下の実録音を参照）。

   (c) が仕事をするのは**静かな部分**である。ステレオ番組を最大偏移から
   32 dB 下げると side/mono は −13.9 dB（(b) は開いている）、
   side-over-noise は 27 dB で取得する。同じ素材をゲート 29 dB にすると
   一度も取得しない。つまり (c) の上側の余裕は約 1 dB。下側は無音時の
   ノイズ疑似軸に対するマージン（無音実測 CNR 45/35/25/15 で
   med 22.7 / max 24.2 dB、ゲートまで 1.8 dB。この無音は音声が無音なだけで
   パイロットも搬送波も存在するが、実測ではオフセット 0 / 60 / 1237 Hz で
   同じ値になった（予測ではなく観測。この fixture も他と同じ 1237 Hz で走る）。

   実録音でブロック単位に見ると、拒否されたブロックのうち (b) のみ /
   (c) のみ / 両方で落ちた割合は、optical 82.5 が 19 / 33 / 48%、
   CATV 83.7 が 10 / 71 / 18%、optical 80.0 が 28 / 14 / 58%、
   antenna 91.6 が 0 / 100 / 0%。実際の番組では両者が分担している。

   参照録音 4 本で (c) を 6 dB まで開いたときの音声差は
   −58.5 / −50.7 / −69.6 / −59.2 dB、角度差は 3 本で 5.4° 以内。
   4 本目が番組の狭い optical 82.5 で、開くと −3.4° から −17.6° へ
   流れる。追従値（ゲート閉の間は保持・リークする）ではなく
   **ブロックごとの生の主軸**（`stereo_phase_axis_deg`）で比較すると:

   | 録音 | ゲート通過ブロック | 同 集中度 | ゲート阻止ブロック | 同 集中度 |
   |---|---|---|---|---|
   | optical 82.5 | −7.0° | 1.00 | −17.0° | 0.65 |
   | CATV 83.7 | −3.1° | 1.00 | −4.4° | 0.56 |
   | optical 80.0 | +0.3° | 0.99 | −3.6° | 0.99 |
   | antenna 91.6 | −0.4° | 0.99 | +0.2° | 0.98 |

   82.5 で阻止されているブロックは独自の軸を 10° 離れた位置に、しかも
   緩くしか持たない（集中度 0.65、異方性 0.60 = この定数が対象と
   している疑似軸の値）。side 帯はノイズ比 18.4 dB で、通過側の
   33.2 dB より遥かに弱い。開いたトラッカーはこれを追っている。
   どちらが真値かは確定しない（仮に −17.6° なら事前値 0 の代償は
   side 帯 0.42 dB）が、互いに一致しないブロック群に訊く理由はない。
   内容を持つブロックで測った軸は 4 本とも事前値から ±7° 以内で、
   side 帯にして 0.06 dB。

7. 3 バンド整形 + ブレンド + HF ブレンドの上限ゲイン（既定は中立 1.0）
8. ステレオマトリクス `L=Mono+Side, R=Mono−Side`
9. パイロットノッチ ×2（19 kHz、Q=30）
10. composite→audio リサンプル（`StatefulResampler`、L/R 独立）。
    出力/入力レートの有理数比を使用し、既定の 192k→48k は 1:4、
    192k→44.1k は 147:640。ブロックをまたいで同じ出力グリッドを保持。
    IQ→composite と composite→audio の両方で、既約比の分子・分母を
    各 1000 以下に制限し、超過するレートはフィルタ生成前に `ValueError`。
    音程やサンプルクロックがずれる近似丸めは行わない
    （例: 44,056 Hz、22,050 Hz、11,025 Hz は変換比の上限により非対応）。
    44.1 kHz は単段変換のため、現在の保留履歴方式ではこの段だけで
    6400/192000 = 約33.3 msの遅延（48 kHzの約0.21 msに対し約33.1 ms増）。
    レビュー環境の参考測定では、音声変換1本が約0.9→6.1 ms/ブロック、
    全体RTFが0.545→0.786（約44%増）。標準モードの16 msブロック、
    `emit_align=4` 同士の比較であり、CPU・実行環境に依存する。
    今回は単段構成を維持し、1/4→147/160 の段階化は今後の最適化候補とする。
11. 最終音声帯域制限 — L/R に**同一タップ**の線形位相 FIR
    （48 kHz で 183 taps、通過域 15 kHz / 阻止域 16.5 kHz、遅延 1.9 ms。
    手順 5 の遷移帯写像成分を抑制。同一フィルタのため
    セパレーションへは影響しない。モノ動作時も両インスタンスを
    同一入力で進め、L/R のサンプル数・出力グリッド・LPF state の
    不整合を防ぐ）
12. ディエンファシス（τ=50 μs）
13. **Side NR**（既定 ON、下記）

#### Side チャネル雑音抑制

`SideNoiseReducer`（3.5 参照）が音声出力段で mid=(L+R)/2 を無加工の
まま、side=(L−R)/2 のみを DD-Wiener STFT で雑音抑制します。モノ成分の
音色は完全保存し、ステレオ由来の HF ヒスのみを狙って除去します。

**mono↔stereo 切替連続性**（issue #29 対応）: mid/side NR テールは
stereo・mono 両経路で共有され（`_apply_side_nr`。モノでは side=(L−R)/2≈0
が流れる）、モノ動作中も NR 連鎖と mid アライナが前進します。これにより
(a) stereo→mono 切替では保持中の旧 side が NR オーバーラップを通じて
滑らかにフラッシュされ（旧実装は破棄後に stereo 復帰時 stale 再生:
実測 side RMS 0.31/0.19/床）、(b) 出力レイテンシがモード非依存になり
切替毎の ~16 ms タイムジャンプが消滅。さらに stereo 復帰時は
`_reset_stereo_side_state` が stereo 専用状態（L−R FIR バンク、パイロット
ヘテロダイン/PLL、ノイズ帯 BPF、blend/トラッカーの取得状態）を初期同調と
同じ再取得semanticsでクリアし、復帰 block 0 から stale side なし（最悪
条件 blend 強制 1 で実測 4e-4、適応 blend では ~5e-5）。モノ動作中の NR は
`adapt=False`（時間機構のみ前進するユニティゲインのパススルー。
窓掛けと OLA は動くので、bit 一致ではなく float32 の誤差の範囲で入力を
保存する。実測 2.98e-08 peak / 2.3e-07 相対、振幅 0.05）で駆動され、
スペクトル適応状態（noise floor / power_smooth / DD state）は凍結される —
人工的な side≈0 に最小統計を適応させると床が数秒で崩壊し
（実測: モノ 4 秒で −144 dB）、復帰後 30–50 秒 NR が実質無効になるため。
凍結によりモノ区間の長さに関係なく学習済みモデルが保存され、復帰直後から
NR が有効。残渣は切替を跨ぐ ~2 フレームの床ディップのみ（power smoothing
EMA で有界、上方リークで 1 秒以内に回復）。

**NR オフ（`side_nr_enabled = False`）は「計算するが適用しない」**
（`apply_gain=False`）であり、スキップでもバイパスでもありません。

スキップしない理由: 保持中の side がテイル内に残って再有効化時に
再生され（実測: 無音ブロックに対し mean |side| 0.1875、peak 1.0）、
16 ms のレイテンシが出入りしてタイムラインが跳ねるため — mono↔stereo
で一度直したのと同じ欠陥です。テイルが透明な設定（alpha_floor=1,
beta=0）で off→on を跨いだ出力は、一度も切り替えない出力と同じく
入力との差 4.8e-07（スキップ実装では 5.21）。

バイパスにしない理由: bypass はモデルを凍結するため、オフの間に雑音
環境が変わると再有効化後しばらく古い床で動きます。実測（side 雑音を
20 dB 変えて 5 秒オフ）: 復帰直後 0.5 秒の出力/入力 RMS 比が 0.954、
オンのままなら 0.697、回復に約 5 秒（1/2/3 秒で 0.953/0.892/0.832）。
計算を続ければ 0.703 で、オンのままと区別がつきません。費用は 16 ms
ブロックあたり 1046 us（オン時 1061 us、差は測定のばらつきの範囲）。
バイパスなら 85 us ですが、オン/オフでゲイン以外が変わらないことを
A/B の条件として優先しました。モノラル経路は従来どおり bypass
（side≈0 を学習させないため）。

### 3.4 音声出力（audio_output.py）

`AudioOutput` が PyAudio による再生と、音声 WAV 録音を管理します。

- コールバック駆動再生（`_buffer_deque` でゼロコピー供給）
- 録音は `AudioRecordWorker` へ委譲（ワーカー設計は §2.3 参照）
- `record()` は bounded queue への投入のみで即時復帰
- start / stop / rotation / sidecar は IQ 録音と共通の設計（メタデータは
  3.12 参照）

**クッションと保持**: 再生開始はキューに `_preroll_frames`（1 ブロック分
＋ カードが一度に抱える量）が溜まってからです。これは起動時の 1 回きり
ではなく、`hold()` / `resume()` で作り直します。受信機が「しばらく音を
作れない」と分かっている区間 — 帯域掃引 — では `hold()` でストリームを
止め、キューを捨て、プリロールを再武装します。止まったカードは空の
キューに要求を出せないので、この区間のアンダーランは構造的に 0 です
（4.3 秒の掃引で 68 回 → 0 回、実測）。`resume()` 後は起動時と同じ経路で
クッションを積み直してから鳴り始めます（実測 161–187 ms）。

保持は入れ子にでき（カウント）、`stop_stream()` は PortAudio の graceful
stop なので、カードが抱えている分を鳴らし切ってから戻ります（実測
101–110 ms、このカードの出力レイテンシ 106.7 ms に一致）。選局では
保持しません: 選局が失うのは underrun 1 回（21 ms）で、保持すると
1 回あたり 107 ms 伸びるためです。

### 3.5 フィルタ（filters.py）

| クラス | 種別 | 備考 |
|--------|------|------|
| `LowpassFilter` | Butterworth LPF（SOS） | ストリーミング、状態保持、`reset()` |
| `FIRFilter` | 線形位相 FIR（overlap-save） | mono/side フィルタバンクと、マトリクス後の L/R 共通・最終音声 LPF の両方で使用。タップスペクトル事前計算、ストリーミング状態保持、`reset()` 対応、任意ブロック長でワンショットと厳密一致 |
| `BandpassFilter` | Butterworth BPF（SOS） | 同上 |
| `NotchFilter` | IIR ノッチ | 同上 |
| `DeemphasisIIRFilter` | ディエンファシス IIR | Numba 最適化 |
| `StatefulResampler` | polyphase リサンプラ | グリッド整合、任意ブロック長で厳密 prefix |
| `SideNoiseReducer` | DD-Wiener STFT 雑音抑制 | mid/side の side 専用 |
| `StreamAligner` | ストリーム整合バッファ | side NR の mid 遅延補償 |

#### StatefulResampler

`scipy.signal.resample_poly` はステートレスでブロック端をゼロパッドし、
ブロック境界に過渡ノイズを生みます。本クラスは:
- 前ブロックの履歴を可変長で前置し、拡張ブロックの開始を常に polyphase
  グリッド周期（`down/gcd(up,down)`）の倍数に整合（任意ブロック長・比で
  厳密に一括処理の prefix と一致）
- FIR サポートが受信済み入力で完結した出力のみ放出（末尾の未確定出力を
  持ち越し）。定数レイテンシは half-filter 長。
- `emit_align` は放出境界を丸めるための設定。IQ段では従来の放出単位
  4に固定し、音声レートの分母と切り離す。下流は自身の出力グリッドを保持
- 保留出力のFIRサポートを保持履歴が覆えるよう、生成時に
  `(emit_align−1)×down ≤ half_len×(up−1)` を検証し、違反は `ValueError`。
  サンプル数が一致しても値が劣化する設定（例: 1/4・emit_align=4）も拒否
- 生成後の状態変更等で保留出力のインデックスが保持範囲より前になった
  場合は、`process()` が入力を消費する前に `ValueError`。
  この実行時ガードは個数の欠落を検出するもので、FIRサポートの保証とは区別する。
  設定を変更する際はリサンプラを再生成し、生成時の検証を通す

#### SideNoiseReducer

Mid/Side の side チャネルに対する STFT スペクトル雑音抑制:
- STFT: frame 1024 / hop 256（75% オーバーラップ、Hann 解析+合成窓、
  レイテンシ ~16 ms）。窓二乗和を hop 内の各位置で正規化し、
  hop 512（50% オーバーラップ）でも定常部を振幅変調なく再構成
- ノイズ床: 平滑パワーの最小統計 + バイアス補正。トラッカー入力は周波数
  方向の局所中央値 +8 dB でクランプ(トーン保護 — 定常トーンが自ビンの
  床に吸収されて `alpha_floor` まで削られるのを防止。広帯域ノイズの推定
  挙動は不変)
- 完全なゼロフレームではノイズ床・平滑パワー・DD履歴を凍結し、
  時間方向のOLA処理だけを進める。無音で減衰した平滑パワーが復帰時に
  ノイズ床を引き下げることも防ぐ。推定値が
  数値床（1e-18）以下のビンは次の有効な学習時に再初期化し、その
  ビンの古い DD 履歴も引き継がない。通常の上方リークは維持
- Ephraim-Malah Decision-Directed（α_dd=0.98）による a priori SNR 推定
  → Wiener ゲイン（下限 `alpha_floor`、既定 0.30 = -10 dB）
- 周波数方向 3-bin ゲイン平滑（musical noise 抑制）
- 動作帯域 1.5–15 kHz（低域のステレオ定位を保存）

### 3.6 PLL（pll.py）

`PLL` クラス（Numba 最適化）。パイロット位相追跡（`return_phase=True`）
に使用。標準の FM 復調は既定で discriminator のため、メイン PLL は

### 3.7 自動ゲイン制御（auto_gain.py）

`AutoGainController` が RTL-SDR の手動ゲインステップを用いたソフトウェア
AGC を実装します。

- IQ ピーク振幅を監視し、クリップ / 弱信号が連続すると 1 ステップ調整
- `set_gain()` の USB 転送は `AutoGainWorker` スレッドへ非同期投入
  （処理スレッドをブロックしない、要求は coalesce）
- `disable()` は現ゲインに pin（AGC 保留要求で後から変わらない）
- 起動後 `AGC_WARMUP_SEC`（既定 2.0 秒）は AGC を抑止（JIT スパイク中の
  誤発火を防止）

### 3.8 CLI（cli.py）

`CommandLineInterface`（スレッド）がユーザコマンドを facade API 経由で
実行します。ディスパッチは 1) 完全一致 → 2) **第 1 語**一致（agc / gain /
list / search）→ 3) 数値入力（局番号 / 周波数）の順。プレフィックスでは
なく語単位で照合するため `searchlight` が `search light` と解釈されること
はありません。コマンド部分のみ小文字化し、引数は入力された大小文字を保持
します（ユーザが定義したエリア名や局名のため）。録音ファイル名は
`build_recording_path()` が `recordings/` 下に自動生成します。

`list`（引数なし）はプリセットを表示し、番号選局はこの並びを指します。
`list all` / `list <エリア>` / `search <文字列>` は全カタログを対象とし、
コマンドプロンプトが流れないよう 40 件で打ち切ります（3.9 参照）。

### 3.9 局リスト（stations.py）

全国の送信所カタログと、ユーザによる編集層を合成して返すモジュール。

**二層構成**

- 同梱スナップショット `fm_radio/data/stations.json`: 145 局 983 送信所
  （民放 451 / NHK-FM 532、中継局を含む）。`tools/fetch_stations.py` の
  生成物で、手編集しません。
- ユーザ層 `stations.toml`: Windows は `%APPDATA%\fm_radio\`、他は
  `$XDG_CONFIG_HOME/fm_radio/`（既定 `~/.config/fm_radio/`）。
  `--stations PATH` で差し替え可。読み込みに `tomllib` が必要なため
  Python 3.11 以上でのみ有効で、それ未満では警告を出して同梱リストのみで
  動作します。

**マージ規則**

1. `[[override]]` は**同梱のエントリ**に対してマッチ判定します。改名が
   後続ルールのマッチ対象を変えません。
2. `hidden` 以外の変更は記述順に適用（後勝ち）。
3. マッチした `hidden = true` は記述位置に関わらず優先。
4. すべての `[[override]]` を適用したあとに `[[station]]` を追加し、
   同一キーの既存エントリを置換します。この 2 段は配列の記述順とは無関係
   なので、`hidden` で消したキーを `[[station]]` で再追加することも、
   どちらを先に書いても可能です。

**同一送信所の判定**

周波数を 1 kHz（`FREQ_DECIMALS = 3`）に丸めた値と送信所名の完全一致。
`match_freq_mhz` も同じ丸めで比較します。許容差比較は `nearest()` のみで
使い、これは「どのエントリが同じか」ではなく「チューナーが今どこにいるか」
を問う別の判定です。同一周波数が複数エリアに存在する場合（80.0 MHz は
関東では TOKYO FM、熊本では RKK ラジオ）、同着はプリセット優先で解決します。

**プリセット（`favorite`）**

`favorite` はマージ中のみ三値（未指定 / true / false）で、
`load_stations()` が**マージ後に残った局**に対して bool へ解決します。

| マージ後の局の `favorite` | プリセット |
|--------------------------|-----------|
| すべて未指定 | 同梱の既定 10 波 |
| 一部が `false` | 既定 10 波から該当を除外 |
| 既定 10 波すべてが `false` | 空 |
| どれかが `true` | `true` の局のみ |

判定対象がマージ結果である点に注意が要ります。`[[override]]` で
`favorite = true` を付けた局を、`[[station]]` が同一キー（丸めた周波数と
送信所）で置換すると、その指定は置換された局ごと消え、既定 10 波が
適用されます。これは**ファイル上の前後に依存しません** — マージは
「全 `[[override]]` を適用 → 全 `[[station]]` を追加」の順で固定で、
2 つのテーブルをどちらの順に書いても結果は同じです。順序が効くのは
各配列の内部（同じ項目を変える `[[override]]` は後勝ち、同じキーの
`[[station]]` は後のものが残る）だけです。

既定 10 波は局名ではなく `(MHz, 送信所)` をキーにしており、カタログ再生成で
局名が変わっても同じ送信所を指し続けます。

**エラー処理**

例外を投げません。不正な入力は、影響範囲を最小にして読み飛ばします。

| 不正の種類 | 結果 |
|-----------|------|
| 同梱 JSON が読めない・オブジェクトでない・`stations` が配列でない | 同梱層が空 |
| 同梱 JSON の個々のエントリが不正（辞書でない、名前や周波数が使えない） | **その 1 件のみ**を飛ばし、残りは読み込む |
| `stations.toml` が不正な TOML | ユーザ層を無視 |
| トップレベル `area` が地域名でない（綴り違い・文字列でない・空） | 警告を出し、**地域未設定として扱う**（カタログ全体で命名） |
| `[[station]]` / `[[override]]` の要素がテーブルでない | **その要素のみ**無視し、同じ配列の他の要素は適用 |
| ルール内の**変更**が不正（`hidden` / `favorite` が真偽値でない、`freq_mhz` が有限でない） | **その設定のみ**無視し、同じルールの他の変更は適用 |
| ルールの**選択条件**が不正（`match_freq_mhz` が有限でない） | ルール全体が何にもマッチせず、同じルールの変更も適用されない |
| `match_*` を持たない `[[override]]` | 同上（何にもマッチしない） |

**受信地域 `area`（トップレベル）**

周波数は全国で一意ではありません（983 送信所が 76〜95 MHz の 191 チャンネル
中 173 を占めます）。`area` 未設定だと、ダイヤルを合わせたほぼ何にでも名前が
付き、それが千キロ離れた送信所の名前であることも珍しくありません。東京での
実測では、バンドスキャンが見つけた 12 信号のうち 4 件が北海道・東北・四国の
送信所名で表示されました。

`area` が絞るのは**命名だけ**です。

| 対象 | `area` の影響 |
|-----|--------------|
| `get_catalogue()` / `search` / `list all` / `list <地域>` | **受けない**（全国のまま） |
| ダイヤルの局名（`nearest` / `current_station` / スナップショットの `station`） | その地域に限定 |

限定されたビューでも次の 2 種は残ります。利用者自身が置いたものだからです。

- `[[station]]` で追加したエントリ（`area` に何を書いていても）
- `area` が空のエントリ（同梱データには必ず `area` があります）

指定した地域に 1 件も残らない場合は、警告を出してカタログ全体で命名します。
設定 1 行のせいで何も名乗れなくなるより、そのほうが驚きが小さいためです。

**地域の推定と書き込み**

帯域スキャンが最後まで走ったとき、GUI は `where_this_is()` で受信地を推定します
（地域単位ではなく**送信所単位**で投票する——`band_scan` 参照）。結果が
現在の設定と違うときだけ確認ダイアログを出し、「はい」で
`FMReceiverController.remember_where_this_is(area)` が

1. `stations.remember_area()` でファイルの `area` 行だけを書き換え（指定された
   `--stations PATH` があればそのファイル）、
2. 成功したときのみ命名ビュー（`_here`）を差し替えます（次回起動を待たない）。

安全に書けないときは `WillNotEdit` の文面をそのままダイアログで見せ、ファイルも
命名ビューも変えません（ファイルにない設定で命名するのは、次回起動でも続くと
利用者に言うのと同じだからです）。中断されたスキャン（Stop、デバイス消失、
ウィンドウクローズ）では訊きません。

同梱層が空でもユーザ層は適用されるため、最終的なカタログが空とは限りません
（同梱 JSON が壊れていても `[[station]]` の追加局は残ります）。
問題は `load_stations(warn=…)` のコールバックで通知され、
`FMReceiverController` がこれを stderr へ出力します（`--log` なしでも
設定ミスに気づけるようにするため）。

**生成（tools/fetch_stations.py）**

3 つの一次情報を合成します。

| 出典 | 内容 |
|------|------|
| 総務省「全国民放FM局・ワイドFM局一覧」(HTML) | 民放 FM / ワイド FM 451 送信所、法人名 |
| `nhk.or.jp/radio/include/freq.json` | NHK-FM 532 送信所（総務省の一覧は民放限定） |
| radiko 局リスト (XML) | 民放の愛称 |

愛称は総務省ページのバナー画像スラッグを鍵に突合します（98 社中 73 社が
自動一致、残り 25 社は `RADIKO_ID_BY_LEGAL` の対応表）。**愛称と異なる**
法人名は `legal_name` に残し、検索対象にも含めます。両者が同一の局
（J-WAVE、TBSラジオ、FM802 など 27 社）は重複を避けて `legal_name` を
空にしますが、同じ文字列が `name` にあるため検索はできます。

書き込み前に構造・必須項目・帯域・**出典別**のエリア網羅性・重複
（`(丸めた周波数, 送信所)`）・愛称解決を検証し、同梱スナップショットとの
件数差（出典ごと ±10%）も比較します。失敗時は非ゼロ終了で既存ファイルを
保持します。比較基準が存在しなければ比較をスキップ、存在するが読めない・
`counts` が不正なら失敗。`--force` は件数比較と利用不能な比較基準のみを
免除し、構造検査は免除しません。

### 3.10 帯域スキャン（band_scan.py）

`BandScan` が 76–95 MHz を掃き、何が出ているかを返します。掃引の間は
受信機を借り切ります: 選局し、ゲインを固定し、出力を保持し、
終わったら（キャンセルでも失敗でも）三つとも戻します。

**ホップ**: `hop_centres()` がサンプルレートから中心周波数を決めます。
1.024 Msps では 24 ホップ、実測で約 4 秒。各ホップのブロックは
`SDRReceiver.watch_the_blocks()` が渡す**コピー**で、復調器のキューから
奪いません（奪うと復調器のフィルタがギャップをそのまま引きずり、
掃引自身の雑音より悪い音になりました）。

**ピーク**: スペクトルは 0.1 MHz（`CHANNEL_STEP_HZ`）刻みのチャネルごとの
電力にまとめられ、`peaks()` が「±200 kHz 以内で最も強く、かつ見た範囲の
中央値より 10 dB 以上高い」ものを拾います。中央値を床に使うのは、帯域の
大半が空だからです。**パイロット**: 候補ごとに 0.25 秒（15 ブロック）聴き、
19 kHz を探します。電力は各ブロックの最良値ではなく合計してから 1 回
割ります（最良値は聴く時間が延びるほど雑音を拾いやすくなるだけで、
弱いパイロットには強くなりません）。

**分類**（`classify()`）は 3 つです。

- `CONFIRMED`: パイロットがあり、隣により強いものがない
- `UNCONFIRMED`: パイロットなし。モノラル局とスプリアスはここから
  区別できないので、「ステレオでない」ではなく「未確認」とします
- `LIKELY_SKIRT`: ずっと強い信号のすぐ隣。パイロットの有無では判定
  しません。強い局の裾では、その局のパイロットがそのまま聞こえます
  （82.5 MHz の NHK-FM から 82.1 MHz で 15 dB 実測）

したがって `CONFIRMED` だけでは「独立した局」の証明になりません。

**受信地の推定**（`where_this_is()`）: 確認できた信号のうち、最も強い
ものから 25 dB 以内のものだけを証拠として、**送信所ごと**に投票します。
エリアごとではありません — エリアは広く、東北は帯域のほぼ全域に送信所を
持つため何でも説明できてしまい、東京にいながら関東 8 対東北 9 で東北が
勝ちました。送信所は一箇所で、その周波数群を持つか持たないかです:
東京が 4 件中 4 件を説明し、次点の送信所は 2 件でした。票差が
`HOME_MARGIN`（2）に満たなければ `None` を返します。誤ったエリアは
聞こえるすべての局から名前を奪うので、迷ったら答えない方が安全です。

GUI からの使い方と、推定結果をユーザに尋ねて書き込む流れは 3.14 GUI と
3.9 局リストを参照してください。

### 3.11 品質セルフテスト（quality_selftest.py）

合成 IQ または実測 IQ WAV に対する客観指標の測定モジュール。

- 合成経路: 既知ステレオ音声 → MPX 合成 → FM 変調 IQ → 復調 → 指標
  - THD+N、SNR（参照ベストフィット比）、ステレオセパレーション
  - 指標は 1 秒窓・0.5 秒ホップの**窓中央値**（窓端の過渡に頑健）
  - チャネル障害モデル: `--clock-ppm`、`--carrier-offset-hz`、
    `--multipath-*`、プリエンファシス（既定 ON）
- 実測 IQ 経路（`--iq-wav`）: パイロット SNR 分位点、mid/side の HF
  ノイズ床、ステレオ聴取ペナルティ、CSV 出力
- セパレーション周波数特性（`--sep-sweep`）: **高忠実リファレンス変調器**
  （全 MPX 成分を IQ レートで解析的に直接合成 — リサンプリング皆無、
  pre-emphasis はトーン毎に閉形式適用、位相は台形積分、変調率一定
  正規化）で周波数別のセパレーション/THD を測定。`--hifi-tx` で通常
  評価にも同変調器を使用可能。旧来の
  「Sep ~30dB 床」の主因は blend の stability 項(中立化済み)で
  あり、hifi TX は送信側リサンプリングの影響を排除して blend 中立
  化後の高ダイナミックレンジ測定(1kHz で 43-57dB)での送受切り分け
  を可能にする
- 周波数応答経路（`--sweep-response`）: 単一トーンを対数間隔で掃引し
  （無雑音）、mono（L+R）/ side（L−R）経路の振幅応答を dB テーブルで
  出力。ディエンファシスのロールオフ、15 kHz LPF、19 kHz ノッチの効き、
  side NR の定常成分減衰などを検証できる。`--preemphasis` /
  `--no-preemphasis` と `--side-nr*` を尊重。

### 3.12 録音メタデータ（recording_meta.py）

録音セッションごとに `<base>.json` サイドカーを生成する共通モジュール。
録音開始時に捕捉パラメータ（周波数・ゲイン・レート）を、停止時に
タイムスタンプ・パート一覧（4 GiB ローテーションの分割ファイル群）・
ドロップ数を確定書き込みします。JSON はファイルを開く前に完全シリアラ
イズし（部分書き込み防止）、シリアライズ失敗・書き込み失敗のいずれも
録音を止めません（NumPy スカラーは `.item()` 変換）。

### 3.13 テレメトリ（telemetry.py）

処理スレッドの内部状態を、リアルタイム経路の外から読むための層。

- `StatusSnapshot`: frozen dataclass。周波数・局名・ゲイン・IQ ピーク、
  ステレオ blend・パイロット SNR / ジッタ、L/R レベル（dBFS）、
  ブロック時間（今回・平均・最大・予算）、キュー深さ、各種ドロップ数、
  録音状態、稼働時間を保持。値は float / int / str / bool のみで、
  受信機内部のオブジェクトへの参照を含みません。
- `TelemetryPublisher`: 最新値スロット。スナップショットの writer は処理
  スレッドのみですが、選局は別スレッドから起きるため公開と競合します。
  スナップショットには**そのサンプルが捕捉された世代**を付け、`latest` は
  現在の世代（`SDRReceiver.tuning_generation`）と一致しなければ `None` を
  返します。世代を「公開時に現在だった値」ではなくブロックに紐づけるのは、
  キューに積まれた旧局のブロックも同様に除外するためです。
- 公開できなかった場合は `defer()` で次回期限だけを進めます。これがないと
  失敗が毎ブロック再試行され、1つの不具合がブロックごとの警告になります。
  警告自体も 60 秒に 1 回へ制限し、**公開が成功した時点で抑制を解除**します
  （復旧後の別の障害が最大 60 秒隠れるのを防ぐため）。
- 公開するのは**成功したブロックのみ**です。失敗したブロックを公開すると、
  前ブロックの音声レベルが今回のタイムスタンプと共に出てしまいます。
- 公開レートは既定 20 Hz（`DEFAULT_PUBLISH_INTERVAL_SEC`）。表示側が
  それ以上を使えないため、対象外のブロックでは比較 1 回で終わります。
- `stereo_locked` は `stereo` と blend の両方を見ます。`blend_factor` の
  初期値は 1.0 でモノラル経路では更新されないため、blend だけでは
  モノラル動作中に「ステレオ」と表示されます。
- 対象ブロックで追加される計測は IQ ピークと L/R レベルの 3 つのみ。
  実測でスナップショット生成 67 µs（16 ms 予算の 0.4%）、対象外ブロック
  は 0.18 µs。20 Hz 平均では 0.02 ms/block（予算の 0.14%）。
- 局名の解決（`nearest()` による 983 送信所の走査）は周波数をキーに
  キャッシュします。初版では 322 µs のうち 270 µs がこれでした。
- スナップショット生成が例外を投げても警告ログのみで、音声処理は継続
  します。

### 3.14 GUI（gui/）

PySide6 によるステータスウィンドウ。**任意依存**で、受信機自体は Qt なしで
動作します。`gui/` の外から PySide6 を import している箇所はありません。

- `gui/run()`: `--gui` の入口。PySide6 が無ければ導入方法を stderr に出して
  終了コード 1 を返します。
- `gui/main_window.py` の `ReceiverWindow`: 中央は `QTabWidget` で、
  **Radio** タブに周波数・局名・プリセット、帯域ビュー、ステレオ状態、
  パイロット SNR、L/R レベル、ゲイン（Auto + スライダ）、録音。
  **DSP** タブは 3.14.1。ステータスバー（ヘルス・ブロック時間・
  キュー・ドロップ・アンダーラン・稼働時間）はタブの外です。
  表示中でないタブのコントロールも毎リフレッシュ更新します
  （更新を省くと、そのタブに戻った瞬間にすべて古い値になります）。
- 帯域スキャンは `Sweep`（専用スレッド + signal）が回し、終了後に受信地を
  推定して保存を尋ねます（→ 3.9 局リストの「地域の推定と書き込み」）。モーダルな問い合わせはこの 1 箇所だけで、
  ウィンドウを親にして出します。掃引中は音声出力を保持します（3.4）。

表示は `controller.get_status()` を 50 ms（公開レートと同じ 20 Hz）で
ポーリングするだけで、受信機の内部オブジェクトには触れません。操作は
すべて controller の facade を経由します。ウィンドウは受信機の状態を
自分で保持しないため、リフレッシュとユーザ操作が競合しません。ただし
次の 2 つは例外で、個別に扱っています。

- **ゲインスライダ**: 自動ゲインは毎秒数回値を動かすためスライダも追従
  させますが、ドラッグ中（`isSliderDown()`）は動かしません。
- **Auto チェックボックス / 録音ボタン**: 受信機の状態に追従させる際、
  チェックボックスは `toggled` に接続しているため `blockSignals` で
  signal の往復を止めます。録音ボタンは `clicked` に接続しており
  `setChecked()` では発火しないため、その処理は不要です。

失敗（選局・録音）はステータスバーに `NOTICE_SECONDS`（5 秒）表示します。
ヘルス行は 50 ms ごとに書き換わるため、これがないと読む前に消えます。

GUI モードでは `controller.start_background()` がスレッドだけを起動し、
メインループは Qt が持ちます。ウィンドウを閉じると `quit_event` を立て、
`__main__` が `cleanup()` します。

#### 3.14.1 DSP 設定タブ（gui/dsp_tab.py）

再生したまま変えられる 9 個のパラメータ。いずれも
`quality_selftest._run_demod_diag_iq` がオフライン実験で上書きしている
ものと同じ集合で（→ 3.11）、耳で見つけた設定を同じつまみで測り直せます。
値オブジェクトと facade は 3.1 と `dsp_settings.py`。

並びは耳に届く順です。

| 行 | コントロール | 範囲 |
|---|---|---|
| Blend | スイッチ + スライダ | auto、または 0.00–1.00（0.01 刻み） |
| Side noise reduction | チェックボックス | |
| NR floor | スライダ | 0.00–1.00 |
| NR strength | スライダ | 0.0–3.0（0.1 刻み） |
| L-R 7-12k ceiling | スライダ | 0.00–1.00 |
| L-R 12-15k ceiling | スライダ | 0.00–1.00 |
| Subcarrier phase | スピンボックス | ±180.0 度（0.1 刻み） |
| Mono delay | スピンボックス | 0–`MAX_MONO_DELAY_SAMPLES`（1024） |
| I/Q phase correction | チェックボックス | |

Blend だけスイッチとスライダの組なのは、オフが `None`（適応ブレンドに
任せる）であってスライダ上の数値ではないからです。位相は度で見せ、
設定は radians のまま持ちます。

**読みは 1 回、以後は書くだけ**: 構築時に `get_dsp_settings()` を読み、
あとはリフレッシュで読み戻しません。ウィンドウは 20 Hz で更新するため、
その頻度で読み戻すコントロールは操作中の手と競合します。

**書き方**: コントロール 1 つの変更は `update_dsp_settings` 1 回
（受信機側のロック下で read-modify-write）。スロット切り替えと
Reset all は `set_dsp_settings` 1 回で、9 回に分けません（分けると
途中のブロックが半端な設定で復調されます）。スライダは**ドラッグ中は
書かず**、離したときに 1 回だけ適用します — 1 目盛ごとに書いた実装では
処理スレッドが 1 秒に 40 行のログを書き、SDR キューが 42/80 まで伸びて
音が途切れました。

**A/B**: スロット A と B があり、選ばれている方が編集対象であり鳴って
いる方です。A は窓を開いた時点の設定、B は既定値。切り替えのたびに
`DSP slot A: ...` の 1 行を INFO で残し、9 値すべてを書きます
（「何を聴いていたか」をログ 1 行で答えるため）。Reset all は今いる
スロットだけを既定に戻し、もう一方は比較の相手なので触りません。

**永続化はしません。** 再起動すれば `constants.py` の値に戻ります。
設定ファイルを置くと、constants.py のコメントに書かれた測定履歴が
黙って無効になるためです。セッションが残すのはログです。

掃引中とデバイス消失時はタブごと無効化されます
（`_say_what_can_be_used()` の 1 箇所で決まります）。

### 3.15 エントリポイント（__main__.py）

`python -m fm_radio` / `fm_receiver.py` の起点。コマンドライン引数
（`--light` / `--gui` / `--stations` / `--log`（別名 `--verbose` / `-v`）/
`--debug` / `--log-file`）を解釈し、ログ設定を
行い（有効時）、`FMReceiverController` を生成して `start()` を呼びます。
ログ有効時は GC モニタ（Gen2 コレクションのポーズ時間を記録）も登録し、
音声ドロップ調査に用います。

### 3.16 ログ設定（logging_config.py）

`setup_logging()` がフォーマットとハンドラ（コンソール、任意でファイル）
を構成します。ログはオプトインで、無効時は `logging.disable(CRITICAL)`
により全ロガーが抑止されます（既定はログ無効）。

ファイルは **UTF-8** で開きます。局名・エリア名・送信所名が日本語なので、
プラットフォーム既定（Windows では cp932）だと、UTF-8 で開くエディタから
読めなくなるためです。コンソール側は表示できる文字コードのままです。

## 4. データフロー

### 4.1 IQ サンプルフロー

```
RTL-SDR ─(async callback)→ data_queue ─(processing thread)→
  process_iq_samples ─→ demodulate ─→ enqueue_audio ─→
  AudioOutput.audio_buffer_queue ─(PyAudio callback)→ 再生
```

処理スレッドは録音有効時、復調済みステレオを `AudioOutput.record()` へも
渡します（bounded queue 経由でワーカーが書き込み）。

### 4.2 音声出力フロー

```
(L, R) ─→ audio_buffer_queue ─(callback)→ _buffer_deque ─→
  インターリーブ float32 ─→ PortAudio 出力
```

録音有効時は並行して:

```
(L, R) ─→ _record_q ─(AudioRecordWorker)→
  int16 変換 ─→ writeframes（4 GiB でローテーション）
```

## 5. 信号処理パイプライン

### 5.1 標準モード処理チェーン

```
IQ (1.024 MHz)
  → DC ブロッカ (複素1次 LTI ハイパス, fc=0.1 Hz)
  → IQ LPF (Butterworth N=5, SOS, 状態保持, fc=200 kHz)
  → FM 復調 (arctan discriminator 既定 / PLL 選択可)
  → StatefulResampler 3:16 (Kaiser β=10) → composite (192 kHz)
  → ステレオ復調:
      ├ モノ: 線形位相 FIR (321 taps, 15 kHz)
      ├ パイロット: 19 kHz ヘテロダイン + 複素 LPF (N=9) → 位相 θ
      ├ サブキャリア cos/sin(2θ + φ_offset)
      ├ composite × サブキャリア × 2.0 (前置 BPF なし)
      ├ 3 バンド線形位相 FIR (I/Q, モノと同一タップ数=同一群遅延)
      ├ IQ 位相補正 (異方性ゲート付き4象限トラッカー)
      ├ 3 バンド整形 + 適応ブレンド + HF ブレンド上限
      └ マトリクス L=M+S, R=M−S
  → パイロットノッチ ×2 (19 kHz, Q=30)
  → StatefulResampler 1:4 → audio (48 kHz)
  → 最終音声帯域制限 (L/R 共通 FIR, 15 k/16.5 k, 183 taps)
  → ディエンファシス (τ=50 μs)
  → Side NR (mid/side DD-Wiener STFT, 既定 ON)
  → (L, R) 48 kHz
```

### 5.2 軽量モード処理チェーン

```
IQ (250 kHz)
  → DC ブロッカ (標準と同一)
  → FM 復調 (arctan discriminator, 標準と同一)
  → StatefulResampler 96:125 → × 0.35 → composite (192 kHz)
  → ステレオ復調 (標準と共通の FIR バンク; パイロット LPF のみ order-1)
```

| `STEREO_BLEND_FAST_CLOSE_FACTOR` | 0.5 | ドロップアウト検出時の blend 減衰（16 ms 基準ブロックあたり） |
| `STEREO_BLEND_FAST_CLOSE_SETTLE_REF` | 12.0 | fast-close を許可するまでの整定時間（基準ブロック数 ≈ 190 ms） |
| `STEREO_BLEND_DROPOUT_SNR_DEBOUNCE_REF` | 16.0 | 瞬時 SNR が LO 未満のまま継続したら持続的劣化と判定する時間（基準ブロック数 ≈ 256 ms。実プログラムの連続 LO 割れは最長 131 ms＝軽量ブロック量子化後） |
| `STEREO_BLEND_DROPOUT_RELEASE_REF` | 8.0 | fast-close ラッチを解除するのに要する健全 SNR の連続時間（基準ブロック数 ≈ 130 ms） |
| `STEREO_BLEND_DROPOUT_POWER_DROP_DB` | 15.0 | パイロット電力が自 EMA から崩落したと判定する量（`pow_drop_db = 10log10(EMA / 現在値)`。実プログラムでの最大電力降下は +1.13 dB） |

**blend EMA の非対称性**: 通常の blend EMA は方向で速度が異なります
（閉じる `STEREO_BLEND_SMOOTHING`=0.08 / 開く `STEREO_BLEND_SMOOTHING_OPEN`=0.04）。
ステレオ幅が**広がる**方向は聴感上目立つため意図的に遅くしています。対称だった時点では、
断続的に劣化する受信（劣化ブロックと正常ブロックが交互）で毎ブロック image が上下し
（実測 ±0.14）、可聴なポンピングになっていました。両方向を遅くしても解決しますが、
正常な復帰にも同じだけコストがかかり（blend>0.9 が 0.52→0.98 s）、さらにパイロットレス
同調の整定窓を通る偽 side が増えます（side/mid ピーク 0.54→0.65）。開く方向だけを
遅くすれば、保護応答は即応のまま（ドロップアウト閉鎖 0.197 s は不変）、断続劣化では
image がモノ側へ落ち着きます。なお**真のドロップアウトの閉鎖は後述の fast-close の
担当**で、この 2 定数の影響を受けません。一方**パイロットレス同調の整定窓**は
通常の closing EMA で降りるため 2 定数から構造的に独立ではなく、閉じる側の速度を
据え置いたことで挙動が保たれています。

**ブレンド EMA の時間正規化とドロップアウト fast-close**: blend / パイロット
SNR 系の EMA 係数はすべて 16 ms 基準ブロックに正規化されます
（`alpha_eff = 1 − (1 − alpha)^(block / 16 ms)`）。時間刻みは IQ ブロック長
（`iq_samples.size / iq_sample_rate`）から取り、`process_iq_samples()` 1 回に対する
`demodulate()` 1 回だけが消費します（composite 直接呼び出しは composite 長へ
フォールバック）。これにより、実運用ブロックが 16384 サンプル @ 250 kHz
（≈65.5 ms）の軽量モードでも、標準モード（16384 @ 1.024 MHz = 厳密に 16 ms）と
同一の時定数になります。加えて、パイロット劣化時は 3 系統の検出器
——(a) パイロット電力が自 EMA 比 `STEREO_BLEND_DROPOUT_POWER_DROP_DB` 以上の崩落、
(b) 瞬時と EMA の両パイロット SNR が `STEREO_BLEND_PILOT_SNR_DB_LO` 未満、
(c) 瞬時 SNR が LO 未満のまま `STEREO_BLEND_DROPOUT_SNR_DEBOUNCE_REF` 基準ブロック
継続——のいずれかが成立し、かつ整定ガードを越えている間、blend を基準ブロック
あたり `STEREO_BLEND_FAST_CLOSE_FACTOR` 倍で閉じます。発火した fast-close は
**ラッチ**され、瞬時 SNR が `STEREO_BLEND_DROPOUT_RELEASE_REF` 基準ブロック連続で
健全になるまで解除されません（アタック速・リリース遅の受信機的挙動）。解除条件を
1 ブロックの回復にしていた時点では、断続的劣化（劣化 3 ブロック + 正常 1 ブロック）で
blend が 0.01↔0.26 を 5 秒間に 37 回往復し、可聴なステレオ幅ポンピングになりました。
解除側は LO より高い復帰レベルではなく**同一 LO のホールド**にしています——
レベルヒステリシスにすると中 SNR（7–16 dB、blend が部分的に開くべき領域）の信号が
モノに固定されてしまうためです。(c) は「パイロットは
健在のまま雑音床だけが上がる」劣化のための経路で、(a) は電力が変わらないため
発火せず、(b) は遅い SNR EMA が LO を割るまで約 0.65 s かかります。デバウンス
なしの瞬時 SNR 単独トリガは実音楽のノイズ帯スピルで誤作動するため不採用
（実測: 4 つの参照録音 60 s ずつでの最長連続 LO 割れは 16 ms ブロックで 48 ms
(CATV) / 80 ms (光 82.5)、軽量の 65.5 ms ブロックでは量子化されて 131 ms。
デバウンス 256 ms はこれを ~1.95 倍で上回り、どの録音でも発火しない）。
実測: 軽量モードの実運用ブロックで、パイロットレス同調・ドロップアウトとも
0.197 s で閉鎖、雑音床ステップは blend&lt;0.5 が 0.262 s / blend&lt;0.05 が 0.328 s
（対策前は 0.524 / 0.655 s）、復帰は blend&gt;0.5 が 0.262 s / blend&gt;0.9 が 0.524 s
（&gt;0.5 はリリースホールド分 1 ブロック遅い）。標準モードの通常ブロックは指数が厳密に 1.0 と
なる恒等ショートカットにより、従来と bit 同一です。

## 9. 録音ファイル

自動命名の録音（音声・生 IQ とも）は `recordings/` ディレクトリに保存
されます。各セッションには WAV と並んで `.json` メタデータサイドカーが
生成され、捕捉パラメータ（中心周波数・ゲイン・サンプルレート）、開始 /
停止タイムスタンプ、ドロップ数、そして 4 GiB ローテーションで分割された
`.partNNN.wav` の一覧が記録されます。

WAV フォーマットはデータチャンクサイズを 32-bit で保持するため単一
ファイルは 4 GiB が上限です。閾値手前で自動的に次ファイル（`foo.wav`
→ `foo.part001.wav` → …）へ切り替わります。1.024 Msps / 16-bit / 2ch
の生 IQ で約 16 分ごと、48 kHz 音声で約 6.2 時間ごとにローテーション
します。

サイドカー例:

```json
{
  "type": "iq",
  "file": "20260510_213606_80.0MHz_IQ.wav",
  "sample_rate_hz": 1024000,
  "center_freq_hz": 80000000.0,
  "gain_db": 20.7,
  "started_at": "2026-05-10T21:36:06+09:00",
  "stopped_at": "2026-05-10T21:54:51+09:00",
  "parts": [
    "20260510_213606_80.0MHz_IQ.wav",
    "20260510_213606_80.0MHz_IQ.part001.wav"
  ],
  "dropped_blocks": 0
}
```
